# 声屿 / Heudio 产品完整文档

> 版本 v0.4 · 2026-10-29 · 前后端分离与 QQ 音乐后端

## 1. 产品定位

声屿是一款结合音乐播放器、场景推荐和文字/语音轻陪伴的个人应用。第一阶段提供网页版，第二阶段考虑 PC 与 Android 封装。

用户通过场景、喜好、天气、时段、日程和对话表达需求，应用选择合适音乐。伴侣定位为有边界的心灵陪伴，不提供诊断或治疗承诺。

## 2. 本次范围与变更

当前 UI 继续使用用户提供的 SoundIsle 视觉与交互：暖黑和琥珀色、顶部导航、四场景、左侧对话、右侧封面律动与歌词、底部固定播放器。

前后端独立运行与部署。音乐主来源调整为用户指定的 QQ Music API，固定 npm 版本 `3.3.5`。原 v0.3 的网易云、酷狗、Navidrome 浏览器直连适配不在当前入口提供；原需求和历史说明保存在 [v0.3 文档](archive/声屿-产品完整文档-v0.3.md)，不代表本版能力。

QQ 凭据和模型密钥由后端保管，天气和模型请求也经应用后端。浏览器仅处理 UI、播放输出、设备语音、声景合成、本机数据与推荐排序。

## 3. 用户路径

### 首次使用

进入主页即可选择场景并播放原创器乐试听。用户也可导入本地音频，无需账号或音乐后端。

### 连接 QQ 音乐

进入音乐库的“连接与账号” → 填写 Heudio 应用后端地址 → 验证 → 读取可用扫码方式 → 用对应 App 扫码确认 → 搜索歌曲或导入数字 ID 歌单 → 播放和查看歌词。

QQ 上游地址由后端管理员设置，页面配置的是应用后端 `/api/v1`。搜索失败、无权限、没有音频地址和没有歌词分别保留真实状态，不制造在线成功结果。

### 开始陪伴

未连接模型时，页面明确标记本机指令演示。用户可用文字或支持浏览器中的按住说话下达简单指令。后端配置模型后，用户选择允许模型、验证连接，再使用自然对话。模型只提出动作，前端验证并执行后显示结果。

## 4. 核心能力

### 场景与推荐

四场景：深度专注、舒缓放空、晨曦跃动、夜泊星海。场景切换联动封面、强调色、环境声预设及候选排序。排序参考曲目场景标签、风格偏好、收藏、排除反馈、天气与夜间时段。

在线歌曲默认没有经过音频情绪分析。当前推荐是规则排序，不是已训练的情绪识别系统；QQ 每日推荐和本人私有歌单专用流程留待后续适配。

自动切歌支持：当前歌曲结束后切换、允许立即切换、仅建议由用户决定。

### 播放器

支持播放/暂停、上一首/下一首、进度拖动、音量和静音、随机/循环、播放队列、收藏、浏览器媒体控制。QQ 歌曲由后端取得账号可用链接并代理音频流，支持单段 Range。

QQ 返回试听标记时页面提示试听；无链接明确失败，不宣称成功或擅自判断版权原因。内置三首原创合成器乐，本地导入使用当前浏览器 IndexedDB。

### 视觉与歌词

封面律动基于 Web Audio 实际能量；流光、字境、星轨和手动配色；可关闭动效并跟随减少动态偏好。“只听音乐”隐藏伴侣区、扩大音乐空间，播放不中断。

QQ 同步歌词和翻译由后端 `/getLyric` 适配；页面可本机导入 LRC / YRC，逐行/逐词高亮、滚动和点击跳转。歌曲缺少歌词时展示真实空状态。

### 自然声混音

雨、潮涌、火、风、咖啡厅五层实时合成，可独立调整、全静音、恢复场景预设。比例可由伴侣动作或快捷纠正修改。

自然声与主播放器播放、暂停、静音、语音降音量和睡眠停止同步；重复播放不会重复创建声源。属于本机氛围模拟，不是录制的真实环境。

### 日程与天气

日程支持本机增删改、单次 ICS 导入，并在对应时段影响场景。重复规则、命名时区展开、设备日历持续同步尚未实现。

天气由应用后端访问 Open-Meteo，用户选择城市或明确授权定位。页面缓存天气并标记陈旧状态，未获得天气不显示固定假数据。天气署名继续保留。

### 专注与睡眠

专注计时结束提示休息；睡眠计时到期渐弱并停止主音乐及自然声。网页需要保持运行，后台冻结或设备休眠可能延迟。

### 语音与伴侣

语音输入使用浏览器 SpeechRecognition，依浏览器和系统支持；朗读使用系统语音。录音不由 Heudio 后端保存。支持播放/暂停、场景、音量、下一首、专注/睡眠、风格偏好与混音动作。

模型接入使用服务端 OpenAI 兼容网关，可配置多个模型 ID，前端只选择允许列表。服务端组织系统提示，不向模型发送日程详情或定位坐标。没有模型时保留明确的本机规则演示。

## 5. 系统与目录

```text
frontend/public/          HTML、CSS、浏览器 JS、试听与封面
backend/src/              API 路由、QQ 适配、天气、模型服务
services/qq-music-api/    上游 Node 服务入口与固定依赖
scripts/                 三服务开发启动与静态构建
deploy/                  Nginx 和三个 Dockerfile
compose.yaml             三服务编排
backend/test/、tests/     服务端契约与客户端回归
```

前端默认使用 `/api/v1`。开发代理和 Docker Nginx 都把该路径转发给后端。独立前端托管可修改 `runtime-config.js` 或页面设置中的后端地址。

## 6. 数据与会话

浏览器保存：偏好、场景、收藏/排除、日程、歌词覆盖、本地音频、应用后端地址。对话仅在当前页面内存；清空对话可立即移除。

应用后端保存：内存应用会话、对应 QQ token、二维码所有权、短时播放链接。浏览器持有随机 HttpOnly Cookie，不可通过页面 JS 读取 QQ token。会话默认一天，后端重启需重新扫码。

模型 Key 由后端环境注入，不进入前端文件、LocalStorage 或应用响应。QQ 上游可选加密会话持久化，应用本身尚未实现数据库或 Redis 会话共享。

## 7. 部署与接口

[部署指南](部署指南.md) 包含本地、Docker、独立域名、模型与会话配置。[接口说明](接口说明.md) 是前端与未来 PC/Android 客户端的 API 契约。

本地运行 `npm ci && npm run dev`；构建前端 `npm run build:frontend`；Docker 使用 `docker compose up --build -d`。

原静态托管地址仅能提供前端；完整 QQ 服务仍需独立后端服务器。前端页面不能代替 QQ Node 服务的运行环境。

## 8. 验证与验收

自动检查覆盖搜索规范化、歌词时间轴、试听标记、Range 音频、Cookie 隔离、二维码所有权、退出与延迟响应、CORS、错误脱敏、模型允许列表、天气参数、声景静音与恢复。

真实本机三服务已启动，并验证健康、登录状态与可用扫码通道。当前出口对 QQ 匿名搜索返回 `network.reset`，真实账号扫码和在线播放尚未完成。Docker 运行器不可用，未做容器实跑。详见 [验证说明](验证说明.md)。

## 9. 后续阶段

2. 提供模型服务配置，完成真实多模型与语音陪伴验证。
