# Heudio v0.4 部署指南

## 1. 三个独立服务

前端负责呈现、交互、音频输出与设备能力；后端提供稳定的应用 API，并保管 QQ 登录态与模型密钥；QQ Music API 使用用户指定的 `@yakult-green-tea/qq-music-api@3.3.5` 独立 Node 宿主。

采用 Node 宿主是为了使用上游原生 QQ / QQ 音乐 App MQTT 扫码能力。此三服务方案不把 QQ 服务放进静态托管或 Worker 中。

## 2. 本地开发

```sh
npm ci
npm run dev
```

入口：`http://127.0.0.1:5173`。应用健康检查：`http://127.0.0.1:3001/api/v1/health`。上游能力：`http://127.0.0.1:3200/login/channels`。

`npm run dev` 会启动三个子进程，Ctrl+C 一同关闭。修改后端代码后可重启总进程，或分别运行 `dev:music`、`dev:backend`（带 watch）与 `dev:frontend`。

## 3. 环境配置

本地把 `backend/.env.example` 复制为 `backend/.env`。QQ 服务的可选配置使用 `services/qq-music-api/.env`。

- `HOST` / `PORT`：应用后端监听地址与端口，默认 `127.0.0.1:3001`。
- `QQ_API_BASE_URL`：QQ 上游内网地址，默认 `http://127.0.0.1:3200`。由管理员配置，客户端不能修改。
- `WEB_ORIGINS`：允许的前端 Origin，逗号分隔，不使用通配符。协议、域名、端口必须完全一致。
- `COOKIE_SECURE`：HTTPS 正式环境设为 `true`，本机 HTTP 使用 `false`。
- `COOKIE_SAME_SITE`：默认 `Lax`。跨站部署如需 `None`，必须同时启用 Secure，但浏览器仍可能阻止第三方 Cookie。
- `SESSION_TTL_SECONDS`：应用会话有效期，默认一天。会话暂存在应用后端内存中。
- `UPSTREAM_TIMEOUT_MS`：普通上游请求超时，默认 20000 毫秒。
- `LLM_BASE_URL`：可信的 OpenAI 兼容地址，通常包含 `/v1`。线上要求 HTTPS，允许本机 HTTP 模型服务。
- `LLM_API_KEY`：仅后端使用的模型密钥。
- `LLM_MODELS`：允许选择的模型 ID，逗号分隔。
- `LLM_DEFAULT_MODEL`：默认模型，应在允许列表中。

多个模型可以由同一个兼容网关提供。多个供应商可先在该网关聚合；当前应用后端不接受浏览器提供任意模型服务地址。

## 4. Docker

```sh
cp .env.example .env
docker compose up --build -d
docker compose logs -f
```

访问 `http://127.0.0.1:8080`。Nginx 提供前端并反向代理 `/api/`；应用后端请求 `http://qq-api:3200`。QQ API 与后端不映射公共端口。

容器使用 Node.js 24；`npm ci` 使用已提交锁文件。前端为独立 Nginx 镜像，应用后端无第三方运行依赖，上游 QQ 服务单独安装其生产依赖。

`QQ_SESSION_SECRET` 由部署平台注入，可用 `openssl rand -hex 32` 本地生成。不要提交实际密钥。设置后，上游启动入口会启用加密会话文件，设备身份和会话文件放在 `qq-state` 命名卷内。复用相同密钥和卷。

Heudio 自身的 Cookie → QQ token 映射目前仍在内存中，因此应用后端重启后仍需重新扫码；上游持久化不等于应用会话已实现持久化。

## 5. 正式入口

保留现有服务器的 HTTPS 反向代理，让其转发到本机 `8080`，并把 `WEB_ORIGINS` 改为真实网页 Origin、`COOKIE_SECURE=true`。此版本定位个人部署；模型服务未提供正式账号鉴权，外网入口应置于已有的个人访问控制之后。

独立前后端域名：

1. 前端部署 `frontend/dist/`。
2. 把 `runtime-config.js` 的 `apiBase` 设置为完整后端地址，例如 `https://api.example.com/api/v1`；也可在网页设置中修改。
3. 后端配置前端 `WEB_ORIGINS`，按实际站点关系设置 Cookie。
4. 优先使用同一站点的子域或统一 `/api/` 反代。跨站 Cookie 被阻止时，改用同站点反代。

不要把 `QQ_API_BASE_URL` 填进前端的“应用后端地址”，前端需要的是 Heudio `/api/v1`。

## 6. 检查

```sh
npm test
npm run build:frontend
```

浏览器操作：验证应用后端 → 读取扫码方式 → 手机确认 → 搜索 → 播放 → 拖动 → 检查同步歌词 → 退出账号。

本次已验证真实三服务的连通性与扫码通道读取。运行环境对 QQ 搜索返回 `network.reset`，尚未用真实账号扫码和验证完整曲库播放。Docker 运行器在当前机器不可用，容器尚未实跑；已提供配置和锁文件，Node 三服务已实跑。

## 7. 常见情况

- 健康检查成功不代表 QQ 搜索成功；分别检查上游网络和登录状态。
- `/music/status` 返回未登录属于正常可达状态。
- 没有链接时显示失败，不自动把它判断成会员或版权原因；可换账号权限范围内的歌曲或音质。
- 音频由后端代理以支持 Range 与 Web Audio，带宽经过后端。
- 未配置模型时仍可使用本机指令演示，不会假装模型已连接。
- 定时依赖页面运行，设备休眠或系统冻结可能延迟。
