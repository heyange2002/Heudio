# 声屿 Android · 0.2.4 开发版

已将通过评审的手机界面接入现有业务。PC 和手机共用 `src/hooks/useSoundisle.ts` 的播放、队列、歌词、阿屿、记忆和语音逻辑，PC 的页面布局保持原样。

## 本机运行

在项目根目录运行 `npm run mobile:dev`，打开 http://127.0.0.1:5174/ 。现在启动的是包含真实 API 的移动端服务，不再是静态原型。

0.2.4 移除手机端访问锁定：连接手机服务后直接进入，不再输入或生成 4 位访问码，设置页也没有「锁定访问」入口。手机服务无需配置 `APP_ACCESS_KEY`；MiniMax Key 仍只保存在服务端。

设备标识使用 HttpOnly Cookie 自动建立和恢复，保留已有的 QQ 授权、记忆与播放票据归属；不再因访问会话超时或重启服务弹出解锁页。Cookie 用于区分设备，不作为访问码锁。PC 和普通网页服务原有的会话策略保持不变。

`npm run mobile:build` 输出到 `dist-mobile/`；`npm run mobile:preview` 仅检查静态构建，不提供 API。部署手机服务时使用 HTTPS，通过 `npm run mobile:start` 启动。手机服务为直接访问模式，API 延续同源、HttpOnly Cookie 和请求来源检查；普通网页服务仍要求访问码。

## 安卓调试包

首次构建需要 Android SDK 36、Build Tools 36.1、Java 17 或更新版本。macOS 的构建脚本会发现 Android Studio 自带的 JDK 和默认 SDK 目录，并可使用系统代理；其他平台通过 `JAVA_HOME`、`ANDROID_HOME` 配置。Gradle Wrapper 的发行包使用官方 SHA-256 校验，可通过 `SOUNDISLE_GRADLE_PROXY` 指定构建代理。

运行 `npm run android:debug`。脚本先构建手机界面并同步到安卓资源，再输出：

`android/app/build/outputs/apk/debug/app-debug.apk`

也可以在 Android Studio 中打开 `android/`，先执行 `npm run android:sync`，再点击运行。

USB 真机调试步骤：

1. 电脑运行 `npm run mobile:dev`。
2. 手机打开开发者选项与 USB 调试，连接电脑并确认调试授权。
3. 执行 `adb reverse tcp:5174 tcp:5174`，再执行 `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`。
4. 打开「声屿」，使用默认的 `http://127.0.0.1:5174` 地址，连接后直接进入。

USB 重连后如无法连接，重新执行 `adb reverse`。更换服务地址：在 App 主页面按系统返回键，选择「更换服务」。线上地址要求 HTTPS。仅调试包允许 localhost / 127.0.0.1 的 HTTP，发布包禁止明文连接；尚未配置正式发布签名。

0.2.3 修复搜索栏输入框挤压按钮导致「搜索」换行的问题，已检查 320–412 宽度和 Android 真机。

## 已接入的功能

- 搜索 QQ 音乐、每日推荐、QQ 收藏、个人歌单及完整分页加载。
- 真实播放、暂停、切歌、进度、播放顺序、自动跳过不可播歌曲、预加载与刷新恢复。
- 真实歌词与点击跳转、播放队列、追加和清空；本机收藏与 QQ 收藏分开，避免误认为已同步账号。
- 阿屿对话、场景选歌、歌单卡片、播放操作，以及短期和长期记忆；清除记忆前有确认。
- 录音、MiniMax 识别、转文字后编辑发送、语音朗读与音色试听；录音时临时静音音乐，结束后恢复。
- QQ 音乐连接配置、实际扫码通道、真实二维码和轮询授权、过期状态及退出授权。授权支持的方式以服务返回为准，没有虚构手机 SDK 授权入口。
- MiniMax Key 保存、替换与移除，模型、音色、音质、语速、自动朗读、个人偏好和 EQ。
- 睡眠定时按实际时间到期，避免暂停或切歌重置计时；结束与取消时恢复原音量。
- 安卓原生容器提供安全区和键盘适配、系统返回和麦克风权限。QQ 授权不支持保存图片后从相册识别，已移除保存入口；需要在电脑或另一块屏幕显示二维码，再用手机扫码。
- Android 0.2 使用 Media3 ExoPlayer 和 MediaSessionService 播放音乐。后台队列、自动切歌、播放模式、定时和通知栏控制由原生服务持有，页面重建时同步服务的当前曲目、进度与状态。PC / 浏览器继续使用原来的 Web Audio 播放器。
- 接入媒体通知、锁屏播放 / 暂停 / 切歌、音频焦点及耳机拔出暂停。返回键选择「退出」、更换服务、或清空队列会停止当前播放；按 Home / 锁屏保留播放。
- 安卓均衡器随设备能力启用；不支持的设备会显示原声提示。语音、录音造成的临时降音或静音在页面转入后台或销毁时释放，避免后台音乐一直无声。

### 用这部手机的 QQ 授权

1. 手机的 QQ 音乐设置中获取授权二维码，点击「在电脑显示二维码」。
2. 在电脑打开同一个服务的 `/#qq-display` 页面。本机调试地址为 http://127.0.0.1:5174/#qq-display 。直接输入手机显示的 6 位显示码。
3. 电脑会显示手机这次授权的二维码。用这部手机的 QQ 扫描电脑屏幕并确认，再返回手机声屿查看授权状态。

0.2.1 修复了有效 QQ 密钥超过旧长度限制时无法生成显示码的问题，仍限制异常超长请求。手机按钮新增生成进度、就近错误提示，成功后自动滚动到显示码；已在 Android 16 真机验证点击后显示 6 位码，并用真实 QQ 二维码验证独立电脑会话取得相同图片。

显示码 2 分钟内有效，授权完成、刷新二维码、关闭手机配置页或显示码过期后失效。电脑仅获取二维码图片，不接收 QQ 凭据，也不替手机轮询或提交授权，因此不会把授权落到电脑会话。显示页无需服务访问码，仍须正确的 6 位显示码。显示码只在服务内存中短暂保存，有容量与尝试次数限制。

0.2.2 将连接重置、超时、用户取消和二维码过期分别提示。查询短暂中断会保留二维码并重试，从 QQ 返回声屿时立即续查；已经取得授权后只重试账号状态，不重复兑换。服务配置或扫码通道读取失败时，仍独立更新成功返回的账号状态。已在切换到可连通 QQ 音乐接口的网络后完成真实扫码，确认手机显示已授权且服务已保存有效会话。

当前服务仍只提供二维码接口，单设备直接跳转授权尚未实现；不使用未经验证的 QQ URL Scheme 模拟可用登录。

## 数据与架构

移动端私人服务默认保存到 `.data/mobile/`，不会改写 PC 的本地配置。MiniMax Key 仅在这个私人服务的 `minimax-settings.json` 中保存，权限为 0600，不回显给前端。该配置供连接此手机服务的设备共同使用，并非多租户密钥系统。

手机只保存播放元数据、本机收藏与偏好；播放链接实时重新获取。QQ 授权留在服务端，客户端使用 HttpOnly Cookie。切换后端地址会切换浏览器来源及对应的本机数据空间。

APK 内置网页资源，通过受限的 `WebViewClient` 在用户选择的服务来源下提供界面，`/api` 请求仍访问真实服务，因此无需放开跨域或将会话凭据转成前端 Token。只拦截打包后的首页、assets 和 brand 文件，不开放文件访问，不跳过 TLS 校验。实现参考 [Android 本地内容与同源访问说明](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)。

0.2 使用 AndroidX WebKit 的 `WEB_MESSAGE_LISTENER` 连接原生播放器，限定为配置服务的精确来源且只接收主框架消息，不使用 `addJavascriptInterface`。消息只携带曲目元数据、操作和播放状态；原生服务独立读取 HttpOnly 会话 Cookie，请求同源 API / 不透明播放票据，禁止跨来源播放和 HTTP 重定向，以免转发认证信息。状态消息带页面实例和操作序号，过时回包不能覆盖新操作；完整队列会持续发送到页面确认接收，之后进度回包不再重复传输整张队列，避免异步启动时漏掉首次快照。不支持该消息能力的旧 WebView 会提示升级，并回退到前台网页播放。

原生后台实现参考 [Android MediaSessionService](https://developer.android.com/media/media3/session/background-playback)。音乐服务不依赖页面轮询来推进队列。语音对话与录音仍属于前台功能，进入后台时取消。若首次选歌尚未返回就切入后台，且原生服务没有正在播放的音乐，会保留准备好的队列，提示返回应用后点击播放。

## 验证与当前边界

`npm run test:mobile` 检查手机选歌到共用音频引擎的链路、QQ 授权轮询、完整歌单、定时，以及手机无访问码启动、服务重启后 QQ 授权保留、设备隔离、请求来源检查、Key 服务端保存和开发资源路径保护。PC 原有 UI、访问安全与配置测试继续执行。

`npm run test:android` 执行 URL / 票据边界测试和 Robolectric 原生服务测试，覆盖页面分离后保留队列、媒体播放器切歌、追加不重置进度、过时操作、原生定时、暂停后的迟到网络错误，以及临时静音恢复。`test:mobile` 还覆盖 JS 与原生状态同步、后台队列接管及页面卸载不暂停音乐。

`npm run android:verify` 会同步最新界面，执行原生测试与 Android Lint，再生成调试 APK。

浏览器测试使用受控接口和音频替身验证交互，Robolectric 在模拟 Android 运行环境中检查服务逻辑。真实 QQ 扫码、账户可播权限、付费模型 / 语音调用，以及其他手机的麦克风、锁屏、通知、来电和厂商电源管理行为仍需真机联调。本次已将 0.2.0 安装到 Android 16 真机（PLK110），使用本机生成的两段测试音频确认了媒体前台服务、按 Home 后连续播放与自动跨曲、熄屏后继续播放、系统媒体键、通知栏可见的暂停 / 继续 / 切歌按钮、页面重载接回原生队列，以及后台定时到期暂停。测试中修复了本地绑定未注册媒体会话的问题，并增加完整队列接收确认，防止异步启动时丢失快照。

这部手机的锁屏卡片布局、耳机拔出及来电行为尚未完成验收。此前音乐搜索 / 播放上游连接失败，后台播放验收使用测试音频；0.2.1 已完成真实 QQ 二维码生成和跨屏显示验证，仍不能替代真实 QQ 歌曲与账户权限验收。

尚未配置正式签名和发布；没有强制停止进程后自动恢复播放的机制，也不承诺绕过系统或厂商的强行停止。网页前台与原生后台的交叉淡入淡出和完整可视化能力不完全相同。QQ 音乐 / MiniMax 需要联网；“离线陪伴”使用服务端规则回复，不是离线运行整个 App。

### 真机验收路径

连接本机服务并完成 QQ 授权后：播放真实歌单 → 按 Home / 锁屏 → 等待跨越一首歌曲 → 用通知栏 / 锁屏暂停、继续和切歌 → 重新打开 App，确认曲目与进度一致。另检查拔出耳机是否暂停、来电后的焦点处理、睡眠定时到期，以及「退出 / 更换服务 / 清空队列」是否停止音频。需要保持 USB 端口转发和电脑服务可用；进入后台不等于离线播放。
